# VoiceInput2PC 电脑文字回传手机设计

## 目标

在保持现有“手机文字直接输入电脑”功能不变的前提下，增加一条由电脑到手机的文字通道。手机端不新增页面，只在现有底部操作区最右侧增加“接收”按钮。

## 界面

手机端底部按钮顺序固定为：

```text
[ 新一段 ]  [ 开始输入到电脑 ]  [ 接收 ]
```

现有标题、状态、输入框、计数、提示和配对流程均不改。“接收”得到的文字直接替换现有大输入框内容，不弹通知、不跳转页面、不显示聊天记录。

电脑端状态窗口增加“发送剪贴板到手机”按钮。用户在 Word、网页或其他程序中复制文字，再点该按钮；接收端只在这次明确操作时读取文字剪贴板，并把它保存为一条待手机接收的文字。

## 数据流

1. 电脑端读取剪贴板纯文字，校验非空、最多 20,000 字且不含非法控制字符。
2. 接收端为文字生成随机编号，并在现有 SQLite 数据库中保存一个待接收槽位；新文字会替换尚未领取的旧文字。
3. 手机点击“接收”时立即暂停向电脑自动输入，通过现有 HTTPS、配对令牌和证书固定连接读取 `/outbox`。
4. 手机验证编号与文字后，以程序方式替换现有输入框、重置输入跟踪状态并持久化草稿，因此不会把收到的文字自动回送电脑。
5. 手机本地保存成功后调用 `/outbox/ack`；电脑仅在编号一致时标记已领取，重复确认保持幂等。

协议继续报告版本 2，使旧手机仍可向新版电脑发送文字；新增端点作为向后兼容能力。

## 异常处理

- 电脑剪贴板无纯文字、为空或超过限制：不改变原待接收文字，并在电脑状态栏说明原因。
- 手机没有可接收文字：保留当前输入框原文，提示“电脑暂无待接收文字”。
- 网络、认证或响应格式异常：保留手机当前草稿，暂停自动输入并提示重试。
- 手机已经保存文字但确认请求失败：文字仍保留在手机；下次接收可能再次得到同一条，不会静默丢失。
- 接收动作与尚在执行的手机发送请求串行处理，已发出的请求可以完成，但后续自动输入保持暂停。

## 范围边界

- 本次不实现文件传输、后台推送、通知、历史列表、顶部标签或独立接收页面。
- 本次不修改尚未进入公开仓库的“文字采集”功能。
- 公开构建不得包含私人 IP、配对令牌、证书或签名材料。

## 验收

- 手机按钮顺序与指定文本完全一致。
- 电脑复制中文、英文、emoji 和换行文字后，可排队并由手机主动取回。
- 收到的文字出现在原输入框，手机保持暂停，且不会自动输入回电脑。
- 无待接收文字、重复确认、错误编号、非法内容和网络失败均不破坏现有草稿或待接收数据。
- 原有手机到电脑输入、首次运行、配对、开机启动和安全测试继续通过。
